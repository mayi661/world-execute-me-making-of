这一轮只做勘察，不写任何渲染代码。

先做的三件事，做完再往下：

1. 用一句话确认你的工作目录是 `<项目根目录>`，并列出你从 `AGENTS.md` 读到的规则里你认为最关键的 5 条（原文摘句即可）。
2. 跑 `npm run storyboard` 与 `git status --porcelain`，把两条命令的实际输出贴在回复里。
3. 确认这三个文件存在并能读：`SPEC.md`、`docs/v4/PLAN.md`、`docs/v4/KIT.md`。缺哪个直接说。

然后做勘察，四件事：

1. **镜头表**：把分镜表里的 87 个镜头按段整理成一张 markdown 表：镜头 id、歌曲时间、画面类型（`interface` / `PLATE` / `CODE`）、一句话说明它在叙事里干什么。
2. **引擎清单**：读 `src/engine/*`、`src/components/*`、`src/scenes/kit.js`，列"已经有什么能力"——三墨分版、字符版画、纸底、错版、撕裂、降帧、光效、里程表计数器、字幕带、打字机、镜头内插版画……每项一句"怎么调用"（函数名 + 关键参数 + 在哪个文件）。
   再列一份"没有、但做我这版会想要"的能力，每项估一句"最省的做法"。
3. **三套改版方向**：每套 150 字以内，必须写清：改哪几段（用段字母 A–I 和秒数）、新增什么图形语言、改造的段落数、大概工作量（以"段落 × 晚上"计）。
   三套要有明显差别，不要三套都是"换个配色"。至少一套是"保留叙事、只换视觉语言"，一套是"保留视觉、换叙事/文案"。
4. **最小第一批**：不超过 3 个镜头，要能满足：一晚上能看到结果、不改共用模块、不影响其他段落。

约束：
- 不要动 `src/`、`config.json`、`data/`、`音頻&歌詞/`。
- 不要在回复里大段引用歌词；歌词一律用行号 `text(i)` 指代。
- 不要 commit、不要 push。

输出：写进 `docs/MINE/SURVEY.md`；对话里只回四段——关键规则 5 条、镜头表摘要（按段各一行）、三套方向、你推荐哪一套以及为什么。
